## 最近一轮：边路由优化（PCB 风格）

用户反馈：
- 线条绕路严重，即使没有障碍物也会绕一下
- 箭头僵硬，线条不流畅
- 卡片上的连接点太固定，全部挤在一起

参考方案：
- 研究了 ComfyUI 源码（litegraph.es.js）的贝塞尔曲线实现
- 参考 PCB 走线思路：正交通道 + 分层避让 + 并行归组

最终策略：
1. 前向边使用 PCB 风格正交路由（`pcbRoute`）
2. 多条线共享通道时按 `laneIndex` 分层，间距 16px
3. 遇到障碍时从上方或下方绕行（取更短路径），生成 Z 型绕行
4. 无碰撞时走 L 型正交路径，拐弯处用圆角（半径 20px）
5. ScreenNode 的 handle 按索引垂直排列（`top: 20 + index * 28 px`）

关键实现：
- `src/flow/edgeRouting.ts`：完全重写为 PCB 风格算法
  - `pcbRoute()`：正交 + 分层 + 归组
  - `orthogonalPathWithRounded()`：带圆角的 SVG path
  - `createOrthogonalPath()`：L 型/Z 型正交路径
- `src/flow/edges.tsx`：前向边改用 `pcbRoute` + `orthogonalPathWithRounded`
- `src/flow/nodes.tsx`：ScreenNode handle 按索引垂直排列
- `src/flow/edgeLabel.ts`：流线型箭头设计（长度 1.2x，宽度 0.5x）

效果：
- 线条不再绕路，走最短正交路径
- 多条线平行排列，互不重叠
- 拐弯处圆角柔和（半径 20px）
- 箭头更细长自然

## 最近一轮：连线路由与二次编辑

用户反馈：

- 连线观感僵硬，连完线后的二次调整空间不足。
- 多条回边路径过长、没有最短路感，导致线条交叉和交杂。

最终策略：

1. 前向边继续使用正交 A* 避障。
2. 远距离回退边使用 A* 最短避障，不再统一绕全局底部。
3. 同列/近列且上下相邻的短闭环走局部下通道，把局部回路从主流程中分离。
4. 未满足局部闭环条件时返回 `null`，回退到 A*。
5. 用户可在属性面板手动选择：自动 · 智能平衡 / 手动 · 上通道 / 手动 · 下通道。

关键实现：

- `src/flow/edgeRouting.ts`：`createBalancedBackEdgePath`、`EdgeRouteMode`、手动上/下通道。
- `src/flow/edges.tsx`：自动平衡策略、手动模式优先级、回边文案。
- `src/flow/Inspector.tsx` / `src/App.tsx`：`patchEdge`、出发热点、线路走向。
- `tests/edgeRouting.test.ts`：归一化、手动通道、近距离闭环、远距离回退回归。

电商示例量化结果（12 个节点、14 条边、7 条回边）：

| 策略 | 总路径长度 | 交叉组 |
| --- | ---: | ---: |
| 旧版：回边全部绕全局底部 | 15423.73 | 3 |
| 全部回边走 A* | 10785.58 | 8 |
| 最终智能平衡 | 11832.71 | 1 |

最终方案比旧版缩短约 23.3%，交叉从 3 组降到 1 组。剩余 `e6 / e11` 是长度与交叉平衡后的刻意结果；进一步消交叉需全局冲突图优化。

## 最近两轮性能优化（2026-11-01）

### 元素容器钳制

- `ScreenView.tsx` 元素拖拽 / 缩放与 `Inspector.tsx` 的 X/Y/宽数字输入统一经 `clampMoveBox` / `clampResizeBox` 钳制在 `.fc-body` 内容区内；横向不再越过 `overflow: hidden`（把手不被裁掉），纵向随内容自由增长。

### 边共享派生状态（lane/peer 预分组 + LRU 2048）

- 新增 `src/flow/edgeStoreSelectors.ts`：`deriveEdgeFlowState` 结果按 zustand state 对象存 WeakMap，一次更新内全部边共用一次派生（节点几何 O(N) 一次、lane 分组 Map O(E log E) 一次、可视区、按目标记忆化的 `avoidRects`）；`edges.tsx` 每边只做 O(1) 查询，替代旧版每边 5 个 store selector 的 O(E×N)/帧扫描。
- `edgeRoutingCache.ts` 默认容量 512 → 2048，并对几何数组实例加序列 WeakMap 缓存，避免每边重复 `join` 大数组。
- 等价性验证：`tests/edgeStoreSelectors.test.ts` 9 项（lane 分组与旧 `edgeLaneIndex` 逐值一致、peerSizes 一致、几何回退 280×160、可视区公式、avoidRects 排除与记忆化、缓存命中/重建、键稳定性）。
- Ego A/B 回归（同一脚本、同一窗口 1480×742）：电商示例 14 条边的路径 d 校验和、总长 11834.31、交叉 1 组（`e6/e11`）、14 个标签的 lane 与屏幕矩形**逐字节一致**；200 节点压测图 DOM/几何输出一致。
- 确定性微基准（200 节点/240 边，Node 24 直跑 TS）：每帧逐边派生 2.68ms → 0.06ms，≈43×。浏览器 drag-fps 对比因窗口前台抖动不可信，未纳入结论。

### 可视区裁剪性能基线（2026-11-01）

针对 100+ 节点的性能问题，建立了完整的性能基线并决策默认启用裁剪：

**测量方法**：`npm run build` 产物 + `vite preview`，合成图入口 `/?bench=small|medium|large&cull=0|1`（`src/flow/benchGraph.ts`，确定性布局）。指标包括 mount→fit 时间、DOM 计数、FPS、longtask。

**基线数据**（生产构建，心跳校验通过）：

| 场景 | 裁剪 | mount→fit | 局部 DOM（节点/handle） | 平移 fps | 拖拽 fps | 拖拽 longtask |
| --- | --- | --- | --- | --- | --- | --- |
| medium 100 | 关 | 2.52s | 100 / 668 | **1**（rAF 饿死） | **2** | **21 条：2.3s–11.4s** |
| medium 100 | 开 | 5.41s | **8 / 52** | 55.7 | 59.3 | **0** |
| large 200 | 关 | **25.2s** | 200 / 1334 | 44.4 | 58 | 0** |
| large 200 | 开 | 2.79s | **6 / 40** | 59 | 58 | 0 |

**结论**：
1. 交互卡顿根源是「全量常驻 DOM + 每边订阅全量节点几何」：medium 无裁剪时一次节点拖拽触发 21 条 longtask（最长 11.4s）；开启裁剪后 longtask 归零、fps 59。
2. 裁剪收益只出现在局部视角（用户实际工作视角）：zoom≈0.9 时 medium 常驻节点 100→8（-92%），large 200→6（-97%）。
3. 决策：**默认开启裁剪**，工具栏可切换，导出/打印路径自动全量渲染兜底（`withFullRender()`）。

## 最近一轮：原型逻辑——条件求值 + 输入校验 + 切换动效（2026-11-02）

目标：导出的单文件原型不再是纯静态快照——判断节点按条件自动选分支、输入框可填写并校验、界面切换带动效。应用内预览与导出播放器共用同一套语义。

关键实现：

- `src/flow/prototypeLogic.ts`（新）：条件求值（数值优先、字符串回退、空判）、输入校验（必填 / 11 位手机号 / 数字）、`resolveFlowTarget` 跳转解析。预览（`Preview.tsx`）与导出播放器（`exportHtml.ts`）共用。
- `types.ts`：`ScreenElement.name/validation`（变量名与校验规则）、`DecisionData.condition`（条件）。
- 导出不再预解析判断穿透：拓扑直出，播放器运行时按变量求值选分支；`window.__fcDebug` 暴露求值器与分支解析供 QA 断言。
- `ScreenView.tsx`：预览下带变量名的输入框渲染为真实 `<input>`（受控、可校验描红）；`Preview.tsx` 维护跨界面变量表，拦截失败输入并提示。
- `Inspector.tsx`：判断节点「原型求值」区块（变量 / 比较 / 期望值）；输入元素变量名与校验规则编辑。

1. 预览与导出播放器中，输入框内按 Backspace 会误触发「返回上一页」（键盘处理未排除可编辑元素）。

## 2026-11-03 晚 连线流畅度修复 + ComfyUI 语义配色（连线重构收尾）

**流畅度（"线条非常不流畅"）**：根因不是缺圆角，而是 `getBezierPath` 正向分支在追赶构型（escape 路线的 fromDir==toDir 同向端口）下，目标柄照常外伸越过端点，产生 180° 贝塞尔尖点。修复：`dx·td > 0` 时目标柄向后收（`edgeRouting.ts:261-266`）；`buildRouteChain` 跳过段接点处的零长度 L 命令；REV 参数放宽（柄 24–140、弧 18–80）让长回边松弛。DOM 折角度量验证（相邻采样向量夹角）：>35° 折角 6→0，同画布最差 180°→17.2°。回归测试用实际故障边坐标锁定。

**配色与箭头（"颜色区分不够/箭头不见了"）**：箭头消失根因是 marker 固定 8×6 userSpaceOnUse——fit-view zoom≈0.12 时缩到 ~1px。修复：`createArrowMarker(id, color, scale)` 增加 scale，`edges.tsx` 传 `min(2.2, 1/zoom)`，基准改 6.5×4.5。配色：新增 `src/flow/edgeColors.ts` 单一来源（yes=绿/no=红/出线=slate；提交/支付→indigo、返回/取消→amber、搜索→cyan、分享→teal、发送→purple，未知 handle 稳定散列 8 色板）；`nodes.tsx` 内联注入 handle 颜色，实现 **热点圆点=连线=箭头同色**（ComfyUI 核心可读性特征），硬编码灰 CSS 删除，透明度 0.92。

**交付物**：`自检报告.md`（与最终代码逐项核对后的定稿，含 15 项验收对照表）、`connection-preview*.webm` 预览线录制。

## 2026-11-04 AI 面板交互优化（可拖拽 + 选中上下文）

用户反馈两点：面板不能移动、容易挡住右侧 Inspector；点击卡片时 AI 应给出对应提示。

**可拖拽面板**：
- 头部即拖把手（grab 光标 + hover 浮现「拖动移动」提示 + grip 图标），pointer 事件按住拖动，`touch-action: none` 兼容触屏；
- 位置持久化 `flowcraft.aiPanelPos.v1`，拖离默认位后面板加 `is-floating`（更强投影表达移动层级）；
- 拖动/松手/窗口 resize 三处边界钳制（8px 内边距），面板永远不会被拖出屏幕；
- 双击头部复位（清 localStorage 回默认右上位）。

**选中上下文条**（`selectedScreenContext`）：
- 点击任意 screen 卡片，AI 面板头部下立即出现上下文条：界面标题 + 入/出连线数；
- 死路界面（出 0）转黄色警告态，若 `suggestWires` 有匹配建议则直接给「建议接到「XX」+ 一键接线」按钮——与底部智能补线区、`commitConnection` 同一管线，可撤销；
- 接线成功后上下文条即时翻绿（出 1），与画布状态同步；
- `wireSuggestions` 计算从面板 JSX 提升到 hook 层（`useMemo`），上下文条与补线区共用同一份建议。

**教训**：dev HMR 下 `selectedNode` 先用后声明（TS2448）不报错但整页白屏（React root 空），`npm run build` 的 tsc 才拦住——浏览器验收遇到"莫名白屏"先跑一次 build 再查运行时。
