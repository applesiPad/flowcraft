**三条先说清楚的结论：**

1. 交互流程图的操作成本几乎全部压在**「建立一条跳转」这个动作**上。谁把这个动作压到一次拖拽、且拖拽的起点就是"按钮/输入框/卡片"本身，谁就赢【推断，依据见 §3-D1】。
2. 参考产品分成两派：**画布派**（Figma/FigJam、Excalidraw、X6、draw.io、infinite-canvas）把注意力放在"画得爽"，**原型派**（ProtoPie、Framer）把注意力放在"点得动"。交互流程图要求二者同时成立，这也是它一直缺一个标准工具的原因。
3. FlowCraft 的选择是"以原型派的数据模型，套画布派的交互外壳"：界面节点渲染真实 React UI + 热点级 Handle 连线 + 一键预览穿透【核实，见 `src/flow/nodes.tsx:6-34`、`Preview.tsx:50-74`】。

## 1. 参考产品的交互范式拆解

每个对象统一六问：**目标用户 / 连线怎么建立 / 标签与分支怎么表达 / 有没有预览播放 / 对「软件交互流程图」的适配点 / 不适用点**。

### 1.1 Figma / FigJam（画布手势的行业默认值）

- **目标用户**：UI 设计师、跨职能协作团队。FigJam 再往白板/工作坊扩展。
- **连线怎么建立**：FigJam 的连线（connector）是**选中形状后从边缘出现的连接点拖到另一个形状**，或选中两个对象后用快捷键连接；Figma 设计模式本身没有语义连线，靠 Prototype 面板的"从一个 Frame 的元素拖箭头到另一个 Frame"。→ 这条"元素级拖箭头"正是 FlowCraft 热点 Handle 的心智来源【推断：Figma 原型连接的具体 UI 在近两年多次改版，未逐版核实，落地前以官方帮助页为准】。
- **标签与分支**：Figma 的 Prototype 支持变量、表达式与**条件逻辑**——这条在其官方「计划与功能对照」表里明确列出（[Compare Figma plans and features](https://help.figma.com/hc/en-us/articles/360040328273-Compare-Figma-plans-and-features)，条目 "Variables, expressions, and conditional logic in prototypes"）【核实：能力存在性】；条件写在右侧交互面板、画布上只有一条箭头【推断】。官方原型指南：[Guide to prototyping in Figma](https://help.figma.com/hc/en-us/articles/360040314193-Guide-to-prototyping-in-Figma)。
- **预览播放**：有，Presentation（演示）模式是全屏播放原型的地方；本文未抓该功能页原文，故标【推断】。
- **适配点**：画布手势（空白拖=框选、空格拖=平移、滚轮=缩放、双击=动作）是全体用户的肌肉记忆，直接照抄即可，零学习成本【推断：手势细节未逐条核对官方快捷键页】。
- **不适用点**：它的画布是"通用设计工具"，交互流程只是副产物；要评审"这个按钮跳去哪"，得逐个 Frame 翻 Prototype 面板，**图上根本看不见跳转**。

### 1.2 ProtoPie（交互逻辑的可视化范式，但不是流程图工具）

- **目标用户**：交互设计师、动效/传感器原型（手机、车机、可穿戴）。
- **连线怎么建立**：ProtoPie 的核心模型不是"连两个屏幕"，而是**在右侧面板给图层挂 Trigger + Response**（如 Tap → Jump to Scene）。场景之间有"Chain"关系用于串联【推断：ProtoPie 早期文档把场景串联称 Chain，现版本以 Scene 内交互 + Jump 为主；未逐版核实】。
- **标签与分支**：条件（Condition）写在交互条目里，支持多条件组合；分支在面板内以条目列表堆叠，不在画布上画出来。
- **预览播放**：有，且是产品本体（真机预览/扫码）【推断：未抓官方文档原文】。
- **适配点**：证明了"用真实控件承载交互"的可行性——用户在原型上点的是**真的按钮**，不是带箭头的方块；也证明了"交互数据可以完全结构化（trigger/response/condition）"，这对我们后续做「导出可运行原型」很有参考价值。
- **不适用点**：**它没有流程图**。一堆 Trigger/Response 列表无法让评审者一眼看到"全局有几条主链路、哪里分支"。交互逻辑越复杂，面板越像代码。
- 结论：**借它的"控件即交互入口"，不要借它的"面板列表"**。

### 1.3 Framer（网页原型的连线路数）

- **目标用户**：营销/落地页设计、Web 原型。
- **连线怎么建立**：Framer 的 Prototype 交互走**选中图层 → 右侧 Interactions 面板 → 选 Navigation/动作**的路线；早期版本有过画布上的连接点（connector）拖拽，后续版本弱化【推断：Framer 产品迭代快，连线 UI 是否仍存在需实测当前版本，本文不作为依据】。
- **标签与分支**：靠变体（Variants）+ 条件跳转，标签在面板。
- **预览播放**：有（Preview / 发布站点）【推断：未抓官方文档原文】。
- **适配点**：Variants 与"状态"的映射，对"同一界面的不同状态（空/加载/错误）"这类需求有借鉴意义。
- **不适用点**：为"网页"而生，手势/滚动/响应式的模型比移动 App 简单，也不产出流程图。

### 1.4 wireflow（`vanila-io/wireflow`，与 FlowCraft 同栈，最直接的对标）

> 来源：README（`https://raw.githubusercontent.com/vanila-io/wireflow/main/README.md`，本次已 fetch 全文）【核实】。

- **目标用户**：产品经理 / 独立开发者 / 外包报价（它带工时估算与报价，README "Estimates" 段）。
- **连线怎么建立**：【核实】README 原文 "Connect screens from a card's bottom dot to another card." —— **卡片底部的圆点**拖到另一张卡片。注意：这是**卡片（整屏）级**的圆点，不是元素级。
- **标签与分支**：【核实】"Each connection has its own label, line shape (smooth, polyline, rounded polyline), width (1 to 10 px) and colour." 即**边级标签 + 边级样式**，没有分支端口；它的 "Flow" 模板里虽有 "a yes / no choice" 卡片，但那是一张**画着分支的卡片**，不是真正的条件边。
- **预览播放**：【核实】其 README 的 Features 全清单（125 模板 / 连线样式 / 估算 / 分组 / 撤销 / 导出 JPG-PNG / 离线 PWA / AI 助手）中**没有任何播放或预览器**；产物是图片 + JSON。本文未读其源码，"它确实没有播放隐藏入口"属于基于文档的判断，非源码级证明。
- **适配点（可抄）**：
  - 快捷键表完整且贴手（`Shift+drag` 框选、`Esc` 取消选择、`Ctrl+0` 1:1、`H` 隐藏卡片标题）【核实】；
  - 125 个界面模板按 12 类分组 + 搜索 + 可拖拽缩放侧栏，说明"模板库的组织方式"已经验证过；
  - 分组（Group，React Flow parent node）、多选悬浮条（"N selected · Clear"）、自动保存 + 撤销历史写 sessionStorage【核实】。
- **不适用点（我们必须超过它的地方）**：
  - 连线只有**卡片底点**一个出口 → 表达不了"同一个界面上『登录』和『忘记密码』分别去哪"；
  - 没有元素级热点、没有原型播放、没有条件分支语义 → 它解决的是"页面流程"，不是"软件交互流程"；
  - 数据模型（README 的 `edges: [{source,target,type,markerEnd,label,style}]`）没有 `sourceHandle`【核实】→ 一个界面只能有一个出口。

### 1.5 AntV X6（`antvis/x6`）

- **目标用户**：国内 B 端研发/流程编排（审批流、拓扑、DAG 编排）。
- **连线怎么建立**：以 `graph.addEdge({source, target})` 的**代码 API** 为主；交互式拖线要靠 `connecting` 配置（`snap`、`allowLoop`、`allowMulti`、`validateConnection`），端口（port）模型支持多锚点【核实：X6 中文文档（https://x6.antv.antgroup.com/）的 `graph.addEdge` / `connecting` / `magnet` / `highlighting` / `labels` 章节，本轮调研抓取到原文；另见 01 报告 §3】。
- **标签与分支**：边 `labels` 可挂任意文本/HTML；分支靠不同 port 或不同边颜色，没有"分支节点"这类一等公民。
- **预览播放**：无（它是图编辑器内核，不是原型工具）。
- **适配点**：端口模型天然支持"一个节点多个出口"，如果只做"框+线"的流程图，X6 是最省事的【核实，见 01 报告 §3】。
- **不适用点**：命令式 API（`graph.xxx`）+ React 状态同步要写胶水；HTML 节点是 `x6-react-shape` 的独立包，节点内做"真实界面 + 每元素 handle"要自己撑起来。操作范式上，它默认是"从端口拖线"，视觉语言偏**工程图**而非**产品图**。

### 1.6 maxGraph / draw.io（图形编辑器的正统范式）

- **目标用户**：工程师、画架构图/ER 图/泳道图的人；draw.io 是它的产品形态。
- **连线怎么建立**：draw.io 的招牌交互是**悬停形状 → 四周出现四个蓝色方向箭头 → 点箭头即克隆并连线**；把形状库里的形状拖到箭头上也能直接连上【核实：[Connect shapes quickly](https://www.drawio.com/docs/manual/connectors/connect-shapes/)，原文 "Hover over an existing shape on the drawing canvas and four blue directional arrows appear."；还有 `Alt`+点形状库一键加并连、`Alt+Shift+方向键` 克隆并连】。固定/浮动连接点见 [Floating vs fixed connectors](https://www.drawio.com/docs/manual/connectors/connector-fixed-vs-floating/)。
- **标签与分支**：边可双击加标签、可加拐点、可正交/曲线路由；分支靠"多个出口 + 各自标签"。
- **预览播放**：无。
- **适配点**：**"悬停出连接点"是我认为最正确的画布级交互**——它把"我能不能从这连出去"变成即时可见的 affordance，而不是让用户先猜。
- **不适用点**：节点是矢量图元，塞不进真实 UI；交互语言（对齐吸附、100+ 样式、XML 导入导出）对"交互流程图"是过剩能力；学习曲线陡【核实，见 01 报告 §3/§6.2】。

### 1.7 Excalidraw（手绘白板）

- **目标用户**：快速草图、讨论、教学。
- **连线怎么建立**：选中箭头工具后**从 A 元素拖到 B 元素**，松手即自动绑定（`startBinding`/`endBinding`）【核实：`@excalidraw/excalidraw` 类型定义 `element/types.d.ts` 的 `startBinding/endBinding` 字段，01 报告 §8 已确认】。
- **标签与分支**：箭头可挂文字（text 元素通过 `containerId` 归属到容器），但**没有分支语义**，标签只是浮在边上的文本。
- **预览播放**：无（它是绘图工具，不是原型工具）。
- **适配点**：**"拖动即绑定"的确认手感**值得抄——松手瞬间边立刻吸附并对齐，用户不需要二次确认。
- **不适用点**：元素类型是封闭联合类型，无法自定义 React 元素 → 不可能渲染真实界面【核实，见 01 报告 §3】。手绘风外观与本产品的"接近原生"目标正相反。

### 1.8 infinite-canvas（`basketikun/infinite-canvas`，节点层参考、连线层反面教材）

- **目标用户**：AI 生图/视频工作台的设计师。
- **连线怎么建立**【核实，原本地 clone `repo/`，已删除】：
  - 每个节点左右各一个圆点，**悬停/选中/连线中才显形**：`visible={hovered || isSelected || isConnecting}`（`web/src/components/canvas/canvas-node.tsx:446-447`）；
  - 左点 = target，右点 = source，`onMouseDown` 直接进 `onConnectStart`（同两行）；
  - 所以是**节点级、单出口、固定左右**的连接方式。
- **标签与分支**：无标签、无箭头、无分支——`canvas-connections.tsx` 全文没有 `<text>`/`marker-end`，`CanvasConnection` 只有 `{id,fromNodeId,toNodeId}`【核实，`web/src/types/canvas.ts:100-104`；01 报告 §4 有完整证据】。
- **预览播放**：无。全仓库 `preview` 命中都是图片预览弹窗/对话引用，没有原型播放器【核实：`grep -rln "preview" web/src` 命中文件逐一确认】。
- **画布手势**：空格按住临时平移、`Ctrl` 临时平移、中键平移、滚轮缩放，且对弹窗/浮层做了 `data-canvas-no-zoom` 排除【核实，`infinite-canvas.tsx:35-70, 89-116, 199-206`】。→ **手势层是成熟的，可以放心对齐**。
- **适配点**：① 节点内渲染真实 React UI 的做法；② 悬停才出现连接点的"降噪"策略（连线时不希望满屏圆点）。
- **不适用点**：连线层硬编码"右中点 → 左中点"、无端口 id、无标签、插件 SDK 不作用于边层（01 报告 §4 全文）→ 交互流程图的核心语义（哪个控件 → 哪个界面 → 什么条件）**无处存放**。

### 1.9 小结：同一件事在八种工具里的成本对照

- "从元素拖出来就能连"：FigJam（原型侧）、draw.io、Excalidraw、FlowCraft。
- "从节点/卡片拖出来"：wireflow（卡片底点）、infinite-canvas（节点左右点）、X6（端口）。
- "在面板里写"：ProtoPie、Framer、Figma Prototype 的条件。
- "图上根本看不见"：ProtoPie / Framer / Figma 的交互数据（除 Prototype 箭头外）。
- 由此得到 FlowCraft 的定位：**画布上可读（像流程图）+ 元素级语义（像原型工具）+ 能播放（像 ProtoPie）**。

## 2. 六维对照表

评分口径：**5 = 直接可用，几乎不用二次开发；3 = 能做但要自己补关键能力；1 = 方向性不适配**。评分为【推断】，依据是上文各节的核实事实 + 01 报告的工程量估算。

| 产品 / 库 | 建立连线的操作成本 | 分支表达能力 | 界面保真度 | 预览 / 走查 | 学习成本 | 适配度（1-5） |
| --- | --- | --- | --- | --- | --- | --- |
| **FlowCraft（本原型）** | **5**：拖热点圆点→目标，一次手势完成"控件→界面" | **4**：判断节点 是/否 双出口 + 边标签；缺"多路分支/条件表达式" | **4**：13 类真实 UI 元素、手机外壳、状态栏；不能自由排版 | **4**：P 键播放、穿透判断/动作、面包屑、返回 | **3**：需教"拖热点"与"空格平移" | **5**（自身基准） |
| Figma / FigJam | 3：元素拖箭头（Prototype），但数据藏在面板 | 3：条件逻辑在面板，画布不可见 | 5：本身是设计工具 | 5：Presentation 事实标准 | 4：专业工具，学习曲线长 | 2：不是流程图工具 |
| ProtoPie | 2：面板里 Trigger+Response，最"重" | 4：条件组合强，但不可视化 | 5：真实控件 | 5：真机预览 | 2：概念多（Trigger/Response/Chain） | 2：无流程图，评审不可读 |
| Framer | 3：面板式交互 + Variants | 3：变体+条件，画布不可见 | 5：网页级 | 5 | 3 | 2：偏 Web 原型 |
| wireflow | 4：卡片底点拖拽，很轻 | 2：只有边标签，无分支端口 | 3：线框模板，非真实 UI 组件 | 1：无播放器【核实】 | 5：15 分钟上手 | 3：同类产品，但表达不了"哪个控件" |
| AntV X6 | 3：端口拖拽需配置 `connecting` | 4：多 port + 边标签 | 3：HTML 节点要另装包 | 1：无 | 2：文档/版本混杂 | 4（作底座）/ 3（作产品） |
| maxGraph / draw.io | 4：悬停出连接点，手感最好 | 4：多出口 + 边标签 + 路由 | 2：矢量图元，塞不进 UI | 1：无 | 2：命令/事务/样式模型陡 | 3 |
| Excalidraw | 4：拖即绑定，手感好 | 2：只有文字标签 | 1：手绘风、元素类型封闭 | 1：无 | 5 | 2 |
| infinite-canvas | 3：节点悬停出点，但只有一个出口 | **1**：无标签无箭头无分支【核实】 | **4**：节点内真实 UI【核实】 | **1**：无播放器【核实】 | 4 | 3：只借节点层 |

**读表三点：**

1. 我们的差距不在"连线手感"（draw.io/Excalidraw 都能打平），而在**每元素一个出口 + 出口有语义标签 + 能播放**这三位一体。
2. wireflow 是最危险的对照物：它证明了这套栈能做出来、也证明了"卡片级连线"是它的天花板。**我们的差异化必须落在元素级热点与播放器上**，否则就是它的换皮版。
3. 学习成本 3 分是我们主动接受的代价：原型工具的心智（热点、播放）比纯流程图的"框+箭头"多一层，但换来的是图上直接可读的交互语义。

## 3. FlowCraft 的交互设计决策（问题 → 决策 → 替代方案 → 为什么）

### D1 · 热点 Handle 直接长在界面元素上，而不是"先连两个界面再选元素"

- **问题**：交互流程图的最小语义单元不是"界面 A → 界面 B"，而是"界面 A 里的『登录』按钮 → 界面 B"。如果连线只能连节点，语义就要**事后补录**。
- **决策**：`ScreenView` 给每个 `hotspot` 元素在原位渲染一个 `Handle`，`id = 元素 id`：`<Handle id={el.id} type="source" position={Position.Right} />`（`src/flow/nodes.tsx:17-28`，渲染点 `ScreenView.tsx:154-169`）；`onConnect` 用 `connection.sourceHandle` 反查元素名，自动生成标签「点击「X」」（`App.tsx:183-204`）。
- **替代方案**：(a) 节点级两点连线 + 连完在属性面板挑"触发控件"；(b) 连线中点加下拉选择触发控件；(c) 让用户先建"事件"对象再挂到元素上（BPMN 思路）。
- **为什么选它**：
  1. **一次手势完成语义 + 拓扑**，没有"二次补录"这一步，也就没有"连了忘补"的中间态；
  2. `sourceHandle` 天然是**一对一的数据键**——一个界面可以有登录、注册、忘记密码三个出口（`App.tsx:285-306` 的 `createLink` 同样以元素 id 为键），这是卡片级连线做不到的；
  3. 预览器可以直接 O(1) 命中出口：`edges.find(e => e.source === currentId && e.sourceHandle === elId)`（`Preview.tsx:50-58`）。如果触发控件是事后补录的字段，播放器就得处理"边存在但触发控件未定"的脏数据；
  4. 删除元素时按 `sourceHandle` 级联删边只需要一行（`App.tsx:267-283`）。

### D2 · 同时保留属性面板的"建立跳转"（可达性 / 可测试性 / 触屏）

- **问题**：拖拽依赖 Pointer Capture。README 已记录"需真实鼠标拖拽（自动化点击无法模拟 pointer capture）"【核实，`README.md:25`】——这意味着**核心动作不可自动化测试**；对键盘用户、触屏用户也不友好。
- **决策**：右栏 `LinkBuilder`：两个原生 `<select>`（热点 → 目标节点）+ 一个「建立连线」按钮（`Inspector.tsx:39-92`，挂载点 `:204`），走 `createLink`（`App.tsx:285-306`），生成的边与拖拽**完全同构**（同样的 `sourceHandle/targetHandle/label`）。
- **替代方案**：(a) 只留拖拽（最省代码、最"顺滑"）；(b) 键盘连线模式（选中元素按 C 再点目标，像 CAD）；(c) 全局"连接管理器"列表。
- **为什么选它**：
  1. **可测试**：README 记录了用它实测 12 → 13 条连线、标签自动生成【核实，`README.md:26`】，这是自动化回归唯一可靠的入口；
  2. **可达性**：`<select>` 是原生控件，Tab 可达、屏幕阅读器可读，符合"两条路都能到同一结果"的最低要求；
  3. **触屏**：9px 的圆点 + hover 才显形的锚点是小屏灾难【推断，未实测触屏】，面板路径是触屏的兜底；
  4. 成本极低（约 50 行），不构成维护负担。

### D3 · 用判断节点表达分支，而不是在连线上写条件

- **问题**：分支（"支付成功 → 成功页 / 支付失败 → 重试页"）怎么画？
- **决策**：`DecisionNode` 两个 source Handle——`yes` 在右、`no` 在下（`nodes.tsx:45-47`），配套固定标签「是」「否」（`nodes.tsx:48-49`，样式 `index.css:814-830`）；条件文案在属性面板编辑（`Inspector.tsx:213-235`）；边上仍然有标签，但只承载"点哪个控件"，不承载条件。
- **替代方案**：(a) 单出口 + 边标签写「成功/失败」（wireflow 的做法）；(b) 单出口 + 边标签写完整条件表达式；(c) 边上的"条件表达式"富文本。
- **为什么选它**：
  1. **归属清晰**：一条线写「成功/失败」，在 fan-out（一个界面 5 条出线）时读者无法判断哪个标签属于哪条语义；两个端口是**物理分离**的，颜色也不同（是=绿 `#34d399`，否=黄 `#fbbf24`，`index.css:602-608`）；
  2. **可计算**：分支是节点级事实，BFS 分层（`App.tsx:335-374`）、后续的"路径覆盖统计"、代码生成都按节点算，比解析文本标签可靠；
  3. **有空间**：条件可能很长（「余额 ≥ 100 且已实名」），节点面板放得下，边标签放不下（当前边标签 11px 单行，`index.css:610-621`）。
- **代价（必须承认）**：多一个节点 = 画布更挤、主链路更长。缓解：判断节点是小卡片（不是 320px 的界面），自动布局把它和界面排在同一列（`App.tsx:369`）。

### D4 · 预览播放器自动穿透判断 / 动作节点

- **问题**：播放时用户点的是界面里的按钮，中途夹着的"判断""系统动作"不是可点击的界面。如果播放器停在判断节点上，演示就断了。
- **决策**：`onHotspot` 命中边后，循环下钻：遇 `screen` 停，遇 `decision` 优先走 `yes` 再退化为第一条出边，遇其他节点走第一条出边，最多 24 层（`Preview.tsx:59-69`）；无连线时 toast「「X」还没有配置跳转」（`:53-57`）。
- **替代方案**：(a) 只允许界面→界面的直连（把判断当注释画在旁边）；(b) 遇到判断时弹一个"选是/选否"的对话框；(c) 播放器只走用户手动点的路径，不做穿透。
- **为什么选它**：
  1. **演示优先**：走查的第一诉求是"这条主链路能走通"，默认 `yes` 让主链路零配置可演示（`Preview.tsx:67`）；
  2. **24 层是防环保险**：图上允许成环（返回、重试），下钻必须有上限，否则一次点击能挂死页面；
  3. **toast 是错误暴露机制**：静默不动最糟，用户会以为"点击没生效"；明确告诉他"这个控件还没接线"（`:56`），顺手完成一次自检；
  4. 保留 `no` 分支的演示能力作为下一步（"切换分支"开关），当前不阻塞 MVP。

### D5 · localStorage + JSON 导出，而不是先上云

- **问题**：MVP 没有后端，但用户不能忍受"刷新就没了"。
- **决策**：`nodes/edges` 变化后 400ms 防抖写入 `localStorage["flowcraft.flow.v1"]`（`App.tsx:36, 89-95`）；启动读档 + 2.2 秒提示「已恢复上次编辑的流程」（`:63-87, 591`，样式 `index.css:670-678`）；`导出 JSON`（`:377-384`，带 `version: 1`）与 `导入`（`:386-404`，非法文件 `alert`）；`Ctrl+S` = 导出（`:434-438`）。
- **替代方案**：(a) IndexedDB / localforage（infinite-canvas 用来存图片）；(b) Supabase / 自建 API；(c) File System Access API（直接写本地文件）。
- **为什么选它**：
  1. **零运维、零账号、零隐私条款**：产物不出浏览器，销售演示时不用先注册；
  2. **JSON 可直接进 Git**：README 明确"可纳入 Git 版本管理"【核实，`README.md:31`】——对设计评审来说，diff 一个 JSON 比 diff 一个二进制文件有用得多；
  3. 一个几百 KB 的流程 JSON 离 5MB quota 很远（wireflow 也是同一套 `localStorage` 方案并在 README 里提示 5MB 上限【核实】）；
  4. 数据结构上预留了 `version` 字段（`App.tsx:378`），未来接后端时文件格式即 API 契约。
- **代价**：换机器/换浏览器要手动导入；清站点数据即丢。→ 用「导出/导入」补，并在 README「已知限制」里写明【核实，`README.md:62`】。

### D6 · 打印 / PDF，而不是 PNG 位图导出

- **问题**：需要交付"可评审、可归档"的静态件。
- **决策**：`printFlow()` 用 `getViewportForBounds(getNodesBounds(nodes), 1587, 1122, ...)` 把整图缩放到 A3 横向比例，再 `window.print()`（`App.tsx:406-411`）；CSS `@media print` 隐藏顶栏/左右栏/小地图/Controls/hint/所有 Handle 与热点虚线（`index.css:1452-1492`），`@page { size: A3 landscape; margin: 8mm }`。
- **替代方案**：(a) `html-to-image` 导 2x PNG（wireflow 同款）；(b) 手写 SVG 序列化；(c) 服务端无头浏览器出图。
- **为什么选它**：
  1. **实测否决了 (a)**：README 记录 `html-to-image` 在本机会卡死（连普通 div 都超时），因此移除【核实，`README.md:63`】；
  2. **矢量 + 文字可搜索**：PDF 里标题、按钮文案、连线标签都是真文字，评审能在里面搜索"支付"，位图做不到；
  3. **零依赖、零额外包**：浏览器打印通道，不用引入 500KB 的截图库；
  4. 打印前自动缩放整图，避免"只打印出可视区域"这个最常见的手滑（`getViewportForBounds` 按 1587×1122 比例算，实测缩放 0.48【核实，`README.md:32`】）。
- **代价**：分页由浏览器控制、不能保证像素级还原、不能一键插入文档。位图导出留到"需要贴进 Confluence/Slack"时再做（下一步第 4 条已排期）。

### 4.2 四个必须提前讲的易错点

1. **手势在 2026-10-31 改过一次，旧教程会失效**：旧配置是"左键拖空白=框选、平移只留中键/空格、滚轮被缩放独占"，鼠标用户找不到任何直觉入口，观感就是"画布焊死"。现在：**拖空白=平移、Shift+拖=框选、滚轮=平移、Ctrl/⌘+滚轮=缩放**。
2. **Shift 现在是两个职责**：`Shift + 拖空白`=框选，`Shift + 点选`=加选（`multiSelectionKeyCode` 里同时有 Meta/Control/Shift，`App.tsx:802`）。从 Figma/Excalidraw 来的人按 Shift 加选依然有效；但**框选必须按住 Shift 再拖**，不能直接拖。
3. **预览态的键盘语义变了**：`Backspace` 从"删节点"变成"返回上一屏"。所以 `deleteKeyCode` 在预览时为 `null`（`App.tsx:815`），否则演示时想返回却删了一屏——这是最容易出的事故。
4. **圆点很小，且默认只有一排**：热点锚点 9px（`index.css:573-585`），hover 才放大到 1.35 倍；顶栏「热点锚点」按钮可以整体开关（`App.tsx` 顶栏 → `nodes.tsx` 的 `show`）。图元素多时关掉它，画布立刻清爽；要连线时再打开或直接选中那个界面（选中即显示）。

### 4.3 从空画布到可演示：12 步

1. 双击空白 → 得到第一张「列表页」界面（或左栏点「列表页」）。
2. 左栏拖「详情页」「设置页」各一张到画布合适位置。
3. 选中「列表页」，在右栏给列表项文案改成真实业务名（`Inspector.tsx:174-179`）。
4. 在右栏确认要跳转的元素「热点」按钮是亮的（`Inspector.tsx:181-187`）；不亮就点一下。
5. 从该元素右侧圆点拖到「详情页」左侧 → 自动生成「点击「X」」标签的连线（`App.tsx:189-201`）。
6. 需要条件时：从左栏「流程节点」里拖一个「判断 / 条件」（`Palette.tsx:53-67`），再从上游界面里某个热点的圆点拖到判断节点左侧的入点（判断节点只有一个 `in` 锚点，见 `nodes.tsx:45`）。
7. 判断节点右侧「是」→ 成功页，底部「否」→ 重试页（`nodes.tsx:45-49`）。
8. 选中判断，在右栏把条件写清：「余额 ≥ 100 且已实名」（`Inspector.tsx:218-229`）。
9. 顶栏「⌗ 整理布局」一键 BFS 分层（`App.tsx:335-374`），再手动微调。
10. 按 `P` 预览，从列表页一路点下去；`Backspace` 回退，`Esc` 退出（`Preview.tsx:30-74`）。
11. 顶栏「🖨 打印 / PDF」→ 系统打印对话框里选"另存为 PDF"（`App.tsx:406-411`）。
12. 「↓ 导出 JSON」交给同事/进 Git；对方「↑ 导入」即可复现（`:377-404`）。

## 5. UI 设计层

### 5.1 信息架构：三栏一顶栏

| 区域 | 尺寸 | 放什么 | 为什么这么分 |
| --- | --- | --- | --- |
| 顶栏 | 56px 高（`index.css:47-48`） | 左：品牌；中：撤销/重做、热点开关、整理布局、适应画布、导入导出打印；右：统计 + 「已存本地 时:分:秒」；最右：主 CTA「▶ 原型预览 P」 | 高频且"做"的操作在左，产出/交付在右，**唯一有品牌色的按钮是预览**——它是最该被点的按钮 |
| 左栏 | 236px 固定（`index.css:220-221`） | 6 个界面模板（可拖可点）+ 3 个流程节点 + 一条彩色小圆点提示 | 只放"能新建的东西"。新建入口和学习入口合并，用户不需要找文档 |

**层级原则**：**徽标与 id 在节点外，热点在节点内，Handle 在节点边缘外挑**——三者空间分离，缩放时不会互相压字。Handle 外挑 13px 是关键：它不能盖住按钮文案，否则"点按钮"和"拉连线"会抢同一块像素（拖拽起手区 vs 点击区）。

分四层，各层解决不同问题：

| 层 | 位置 | 文案 / 形式 | 解决什么 |
| --- | --- | --- | --- |
| 1 · 常驻单行提示 | 画布底部居中，11.5px 灰字（`App.tsx:590`） | 「拖动热点右侧圆点连线 · 双击空白新建界面 · 空格拖动平移 · P 预览」 | 四个最高频动作的一句话索引，随时可见、不挡操作 |
| 2 · 右栏空态 | 右栏，未选中任何东西时（`Inspector.tsx:135-145`） | 三条**祈使句**：拖热点圆点连线 / 双击空白新建 / 按 P 预览 | 三条都是"立刻能做的动作"，不是功能说明 |

**两个刻意的选择：**

- **首屏永远可读**：没有存档时用固定视口 `{x:48, y:-110, zoom:0.78}`（`App.tsx:100`）；有存档时 `fitView({ padding: .16, minZoom: .5, maxZoom: .9 })`（`:96`），把"全部塞进屏幕"的下限锁在 0.5。原因：纯 `fitView` 会把整张示例图缩成看不清的小点（实测曾被压到 0.26），第一印象直接崩；要全貌请点「⤢ 适应画布」，它是无下限的。
- **不做引导蒙层（coach mark）**：交互流程图的用户是一次性学 4 个动作的量级，蒙层反而挡画布。常驻提示 + 空态三条已够【推断：未做可用性测试，"够不够"需实测】。

**缺口**：所有节点被删光的**空画布**没有专门空态——只剩点阵背景和底部提示。建议补一个居中卡片：「双击空白处新建第一张界面 / 或从左栏拖一个模板进来」+ 一个按钮【推断，未实现】。

| 文字 | 字号 | 在 0.78 缩放下的实际字号 | 结论 |
| --- | --- | --- | --- |
| 连线标签 | 11px（`index.css:611`） | 8.6px | 临界，建议 <0.6 缩放时隐藏或加粗 |

## 6. 和竞品比，我们 deliberately 不做什么

| 不做 | 谁在做 | 不做的原因 | 什么条件下重新考虑 |
| --- | --- | --- | --- |
| **界面元素的自由拖拽排版**（Figma 级） | Figma、infinite-canvas（节点内 UI） | 元素是 13 种预置类型（`types.ts:1-14`）、由界面容器流式排布。自由排版会把产品变成"画 UI 工具"，而我们的价值是"画流程"；且 90% 的评审场景里，界面只需"够像"而不是"像素级" | 用户开始抱怨"界面不像我们的真实产品"时，接 `@dnd-kit`（README 下一步 #2 已排期） |
| **多人实时协作 / 评论 / 版本历史** | wireflow（无）、Figma（有）、ProtoPie（有） | 需要账号、权限、CRDT/OT、服务器、合规——成本超过其余所有功能之和；单人产出的场景下收益接近 0 | 出现"同一份流程要两个人同时改"的真实需求；当前用 JSON + Git 代替（`README.md:31`） |
| **云端存储 / 账号体系** | 几乎所有商业产品 | 见 D5：localStorage + JSON 已覆盖"不丢"，且省掉隐私政策与运维 | 需要跨设备/团队共享时，JSON 文件格式即 API 契约（`App.tsx:378` 的 `version` 字段） |
| **AI 生成界面 / AI 生成流程** | infinite-canvas（AI 生图）、wireflow（可选 AI 助手） | 目标用户要的是"把我脑子里的流程精确画出来"，生成结果不可控 = 评审价值归零；生成一次要人改十次 | 有稳定的"自然语言 → 结构化流程"模型且用户愿意付费用时；更可能的形态是"AI 补全连线"而不是"AI 生成界面" |
| **PNG 位图导出（暂时）** | wireflow（2x JPG/PNG） | `html-to-image` 在本机实测卡死（`README.md:63`），为避免引入一个不稳定的依赖，先用打印/PDF 覆盖 90% 的交付场景 | 需要贴进 Slack/Confluence 时；届时应改用"服务端/Worker 出图"而不是回退到同一个库 |
| **导出交互式 HTML（暂时）** | 无对标（这是我们的机会） | 需要把预览器 + 数据打包成单文件；在播放器稳定前做，会返工 | 播放器功能冻结后（README 下一步 #3） |
| **连线的手动拐点 / 正交路由编辑** | draw.io、wireflow（可选 smoothstep/polyline） | 当前固定 `getSmoothStepPath`（`edges.tsx:6-15`，`borderRadius 14 / offset 18`），够用且不会画出"麻花线"；手工路由是专业制图能力 | 用户开始抱怨"线穿过了节点"时；先做自动避障（成本更低） |
| **移动端编辑** | 无（wireflow 有窄屏只读适配） | 9px Handle + hover 才显形 = 触屏不可用【推断】；核心用户在桌面 | 只做移动端**查看/播放**（比编辑容易一个数量级），编辑仍留桌面 |
| **对齐吸附 / 智能参考线** | Figma、draw.io | 已有 `snapToGrid 8px`（`App.tsx:561-562`）+ BFS 自动布局，「整理布局」一键解决对齐；参考线是锦上添花 | 用户开始大量手动微调时 |
| **通用流程图能力**（泳道、UML、BPMN） | draw.io、X6 | 做通用 = 和 draw.io 正面竞争且没有胜算；我们的护城河是"界面节点 + 热点 + 播放" | 不做。这是产品定位问题，不是排期问题 |

**一句话总结这页**：我们把"画得像 UI"和"点得动"做到极致，把"画图工具的通才能力"全部让给竞品。宁可被说"功能少"，也不要被说"和 draw.io 差不多"。

### 7.3 已知缺陷（按严重度）

1. **P0 · 自动布局在含环图上不收敛 —— 已修复（2026-10-31）**。旧实现（本报告初稿记的 `App.tsx:341-354`）用"层级更浅才更新"做松弛，我用同一算法在 Node 里复刻：`X→A→B→A` 跑 100,001 次迭代仍未收敛（纯 DAG 3 次收敛）。**现实现已换成 DFS 找 `back` 回边 → 去边成 DAG → Kahn 拓扑最长路径**（当前 `App.tsx:458-549`，回边判断在 `:470-502`，Kahn 队列在 `:516-525`）。去环后的图每次入队即出队一次，**必然终止**。本节结论保留，作为"为什么不能写在线松弛"的记录。
2. **P1 · 连线只做结构合法、不做语义合法 —— 已全部修复（2026-11-07）**。两步：① `ConnectionMode.Loose → Strict`（挡住库层面同类型直连的自由度）；② 实测发现 `onConnectEnd` 落卡兜底管线会绕过 Strict 接管 invalid 拖拽，而 `isValidConnection` 只查目标端——已补源头校验：`fromHandle.type === "target"` 时 toast 拒绝「入口锚点不能作为起点」。Strict 回归 E2E 6/6：反向起线封锁、药丸正向起线、撤销、边选中无回归。
3. **P1 · 拖动节点不进撤销栈 —— 已修复（2026-10-31，本次）**。原先全文件没有任何 `onNodeDragStart`，节点位移不会被 `snapshot()` 捕获，Ctrl+Z 对"我刚挪了一下"完全无效。已加 `onNodeDragStart={() => snapshot()}`（`App.tsx:826`），浏览器实测：位移后 `Ctrl+Z` 精确回到原坐标。
4. **P2 · 画布无错误态**（§5.3）。"热点没有出口"这类语义问题不会在图上暴露，只能靠预览时点出来。
5. **P2 · 空画布无空状态**（§5.4）——当前已有"空画布"分支（`App.tsx` 里 `nodes.length === 0` 的区块），但引导按钮的完整性未验证。
6. **P3 · 节点标题/连线标签不能原地编辑 —— 已全部完成**（节点标题 2026-11-04 bf29ae1；连线标签 2026-11-07，EdgeLabelRenderer 的 pointer-events 结论已落地：标签文字补 `pointer-events: all`，目标芯片保持只读）。
7. **P3 · 撤销栈是整份快照**（`App.tsx` 的 `past`/`future` ref），80 步上限，大图时内存与性能都会退化【推断：未实测大图内存】。

**回边路由的一个已知边界**：lane 高度只取"两端节点底部的较大值 + 56"，不避让**其它**卡片。当前样例里回边都朝向画布左侧、通道落在所有卡片下方，所以安全；但如果未来某条回边的两端都在画布中部，它的通道可能从中间某张卡上横穿。彻底解决需要全局路由（绕障），那是另一个量级的工程，暂记为已知限制。

**一个值得记下的排查坑**：中途出现过"连线全部消失、点节点没反应、取景不生效"的假故障，根因是**标签页处于 `visibilityState: "hidden"`，`requestAnimationFrame` 不再触发**——React Flow 的取景、连线测量都跑在 rAF 上。实测对照：`rafFires=false` 时 0 条边、视图停在 `scale(1)`；切到前台 `rafFires=true` 后立刻恢复 12 条边与 `scale(0.5)`。**看到同类现象先查标签页可见性，别改代码。**
