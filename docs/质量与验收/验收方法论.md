# 验收方法论（E2E 自动化踩坑手册）

> round8–round11 里逐轮实锤的自动化验收限制与可靠做法。写新验收脚本前先读这份。
> 最后更新：2026-11-21

## 本环境（ego lite + headless Chromium）的硬限制

| 限制 | 表现 | 可靠做法 |
| --- | --- | --- |
| **合成器不产帧** | `Page.captureScreenshot` 必超时；**CSS transition 永远停在 progress 0**（`CSSTransition startTime:null, currentTime:0`，inline 值读不回 computed） | 不截图，用 DOM 诊断（`getBoundingClientRect` + `elementsFromPoint` + computed style）；**断言读 style 属性（意图值），不读 computed**（仅对依赖 transition 的属性） |
| WAAPI 可用 | 光带等 JS 驱动动画正常 | 动画类效果优先用 WAAPI 而非 CSS transition |
| `page.setViewportSize` 不存在 | `?.` 静默吞掉调用，假 PASS | `await page.cdp("Emulation.setDeviceMetricsOverride", {width, height, deviceScaleFactor: 0, mobile: false})` + 等 ~900ms 稳定 |

## React 19 合成事件的边界

- 合成 `mousedown/mouseup/mousemove/click/dblclick` **能**触发 React 委托处理（连线拖拽、选中、药丸起线全链路可用）。
- 合成 `keydown`/`blur` **不能**触发 React `onKeyDown`/`onBlur`（round10 对照实验：`editingLeft:1` 不提交）。
- 可靠组合：进入编辑态用合成 `dblclick`（真实 CDP 双击的第二击被 RF 节点拖拽吞掉）；键入与提交用**真实 CDP 键盘**（`page.keyboard.press("Control+a")` + `type()` + `Enter`）。
- `window` 层原生监听（如撤销的 Ctrl+Z）可用 `window.dispatchEvent(new KeyboardEvent(...))` 触发。

## React Flow v12 行为要点（round11 实锤）

- 根元素**没有** `connectionindicator` 类（该类只挂 handle 级）——别再写 `.react-flow.connectionindicator …` 根选择器；拖线态信号用 `useConnection` 驱动的自定义属性承载。
- 连线有 **1px `connectionDragThreshold`**：mousedown 只预备，**派发 mousemove 超阈值后才进入 inProgress**——合成拖拽先 move 再断言。
- **CSS 扩大 handle 命中区不可行**：`getClosestHandle` 用 store 缓存的 `handleBounds`（DOM 快照），CSS 改尺寸不触发重测；强行 `updateNodeInternals` 会把已有入线锚点拽到卡心。整卡命中 = `onConnectEnd` 落卡兜底 + 连线预览卡面命中测试的组合。
- RF `addEdge` 对重复 source/target/handle **静默 no-op**——建线断言要用不存在的边对（医院示例 17 条边，`d-queue-status yes → n-pay-medical` 是安全新对）。
- 落卡兜底按 `mouseup` 事件的 `clientX/Y` 反查节点——合成 mouseup **必须带坐标**。

## 断言纪律

- execCommand 探针会**说谎**：它直接改 contentEditable 的 DOM，React state 没提交——编辑类断言要打到 Inspector 输入框，不能只看画布 DOM。
- 边 SVG 组里第一个 `<path>` 是箭头 marker——选 `path.react-flow__edge-path`。
- QA 探针边数用 `window.__fcQA.collect().counts.edges`；医院示例当前 **17** 条边（`?example=ecommerce&cull=0` 加载，参数名是历史遗留）。
- `n-doctors` 有 **4** 条相连边（e1/e2/e14/e15），淡化断言按 13 淡 4 亮算。
- 心跳式长计划（见 [变更详情/2026-11-04-冲刺工作计划.md](../变更详情/2026-11-04-冲刺工作计划.md) 的恢复指引）：动手前先 `npm test` + `npm run build` 确认环境绿——**HMR 会掩盖 TS 错误**，白屏先跑 build。
